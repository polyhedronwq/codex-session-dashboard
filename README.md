# Codex 会话仪表盘

![CI](https://github.com/polyhedronwq/codex-session-dashboard/actions/workflows/ci.yml/badge.svg)


给 Codex 桌面版加一个**会话仪表盘面板**和一条**输入框下方的状态栏**：看轮次与步数、token 消耗、缓存命中、上下文占用，以及**这条对话占用了多少周额度**。

> **非官方项目**：与 OpenAI 无关联，未获其认可或支持。
> 通过本机调试端口读取 Codex 的会话日志与页面状态，**Codex 更新后可能失效**。

![底栏](shots/layout-final.png)

## 它解决什么

Codex 桌面版能看到「这一轮用了多少」，但很难回答另外几个问题：

- 这次工作**一共**花了多少 token？缓存命中多少？
- 上下文还剩多少空间，什么时候该开新对话？
- **这条对话吃掉了我多少周额度？**（区别于账号总量，Codex 自己的用量页才看得到）
- 刚才那一轮到底跑了哪些工具、哪个子代理在干活？

## 两个部分

### 1. 状态栏（注入到输入框下方）

```
⚡ 12 轮 47 步 · 最近 30.8 tok/s  |  🗄 4.5M tok · 缓存命中 97.1%  |  ◔ 1.71%  |  仪表盘
```

- 三项指标都能点开明细弹层；再点一次关闭，点弹层外部也关闭
- 额度是**按会话归属**的周限额占比，取自 ChatGPT 用量接口；新对话在服务端统计出来之前显示 `—`
- 底栏出现异常时会保留一个提示点，鼠标悬停看原因，不会整条消失

### 2. 仪表盘面板（Codex 标签页里的 MCP App）

| 页签 | 内容 |
| --- | --- |
| 概览 | 轮次/步数、最近一轮速度、累计 token、缓存命中、上下文占用、本会话额度 |
| 统计 | 每轮的步数、上下文长度、输入/输出、缓存命中、首 token、速度 |
| 轨迹 | 按轮次展开的工具与事件时间线 |
| 代理 | 子代理图、工作足迹、沙箱姿态、变更记录、代理间消息 |

## 环境要求

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11 |
| Codex | 桌面版（MSIX）。**本项目在 26.1111.2228.0 上验证**，其他版本可能失效 |
| Node.js | 18+（注入器用） |
| Python | 3.10+（面板服务与指标计算，仅用标准库） |
| Playwright | `npm i -g playwright`（注入器通过它连接调试端口） |

## 安装

1. 解压发布包
2. 双击 `install.cmd`

安装器会依次：校验包内每个文件的 SHA-256 → 检查依赖（缺什么就问你要不要装）→ 安装到 `%USERPROFILE%\.codex-bar` → 注册面板插件 → 建快捷方式 → 启动底栏并自检。

装完后**用桌面上的「ChatGPT 仪表盘」启动 Codex**。若 Codex 已在运行，请先完全退出——否则快捷方式只是把旧窗口切到前台，调试端口不会打开。

升级：拿到新包后再双击一次 `install.cmd` 即可，会自动备份配置、清理已废弃文件、重启底栏与面板服务。

## 卸载

双击 `uninstall.cmd`。

会停止底栏进程、删除快捷方式、还原 Codex 配置、删除插件目录，并在结束时**自检残留**（进程 / 快捷方式 / 配置段 / 目录），有残留会返回非 0 并列出。

## 安全说明（请先读）

**本工具通过 `--remote-debugging-port` 启动 Codex，该端口没有认证。**

- 端口固定为 `127.0.0.1:9223`，只监听本机
- 但**同一台机器上的任何程序都能连上它并控制 Codex**（读取页面内容、执行脚本）
- 这是 Chrome DevTools Protocol 的固有性质，不是本项目的缺陷

因此：**只在自己的个人机器上使用**；共用机器、远程桌面暴露、或装有不可信软件的环境不要开启。不需要时用 `stop-bar.cmd` 停掉底栏并重启 Codex（不带参数启动即可关闭端口）。

## 隐私

- 所有数据来自本机：`~/.codex/state_5.sqlite` 与 `rollout-*.jsonl` 会话日志
- 唯一的网络请求是查询**本会话额度占比**，使用本机已登录的 token 发往 `chatgpt.com`，只读
- 统计页会显示每条消息的**前 200 字**用于认出是哪一轮；如果这不可接受，请勿使用
- 不上传任何数据，不含遥测

## 已知限制

- 仅 Windows，且依赖 Codex 桌面版的 DOM 结构；Codex 大改版后需要更新锚点
- 拿不到逐 token 的时间线，所以「最近速度」是按轮次输出估算的
- 部分会话在服务端没有被归属，额度会一直显示 `—`
- 面板的额度有 15 分钟缓存（未归属会话 60 分钟），不是实时的
- 不支持多窗口同时跟随（跟随当前聚焦窗口）

## 常见问题

**快捷方式点了没反应** — Codex 已在运行。完全退出后重试。

**底栏出现了但数字不动** — 看 `%USERPROFILE%\.codex-bar\bar.log` 与 `health.json`；`state` 会告诉你卡在端口、页面、锚点还是数据。

**底栏显示一个点** — 同上，悬停能看到原因；`health.json` 的 `missingAnchors` 会列出 Codex 改版后缺失的元素。

**面板显示 `—`** — 这条对话还没有被服务端统计；不是所有会话都会有额度数据。

**面板数字不更新** — 关闭面板标签页再打开（Codex 会重启面板服务进程）。

## 开发

```
src/bar/       底栏源码
src/shared/    server.py + panel.html（底栏与面板共用，只维护一份）
src/plugin/    面板插件清单
tools/         安装器、卸载器、路径渲染
verify/        回归套件与单元测试
build.ps1      src → dist → 发布包（含逐文件 SHA-256 清单）
```

```powershell
./build.ps1                          # 构建并同步到本机运行位置
./build.ps1 -NoMirror                # 只出 dist
./verify/run-all.ps1                 # 全量回归（62 项，约 3 分钟）
./verify/run-all.ps1 -Snapshot       # 额外保存截图与数值快照
./verify/run-all.ps1 -SkipBar        # 跳过依赖运行中 Codex 的检查
./verify/post-upgrade.ps1            # Codex 自动升级后的自检（约 40 秒）
node verify/test-resolver.js         # 会话判定单元测试（8 项）
python verify/test_server.py         # 解析层单元测试
./verify/perf-baseline.ps1           # 生成 docs/PERF.md
```

> Codex 桌面版会自动更新。升级后（尤其版本与 `install.ps1` 里记录的验证版本不同时）
> 先跑 `post-upgrade.ps1`：它只检查最容易被页面结构变化打破的四项，几十秒出结论。

回归覆盖：语法、构建一致性、服务端、消费者契约（按 Codex 的读法校验）、面板渲染与数值对账、底栏三态、会话判定、解析单测、安装器生命周期（隔离 HOME）、性能阈值，以及**真实流程**（像用户一样点开面板，同时监听控制台并截图）。

每次跑完会在 `verify/shots/` 生成一组固定截图：底栏、用量 chip、四个页签 × 深浅色，以及真实打开的面板，供人工复核。

路径使用 `{{node}}` / `{{python}}` / `{{server}}` 占位符，源码不含任何本机绝对路径；构建与安装各自渲染。

## 参数与调优

所有时间与阈值都是源码常量，**没有配置文件**——这些值是按实测定的，改之前建议先看依据。下表与代码一致（1.0.0）。

### 刷新与轮询

| 项 | 值 | 位置 | 依据 |
| --- | --- | --- | --- |
| 底栏活跃刷新 | **1000 ms** | `src/bar/injector.js` `REFRESH_MS` | 有一轮正在跑时始终保持这个频率，数据落盘本身就有 1–2 秒延迟 |
| 底栏空闲刷新 | **5000 ms** | `IDLE_REFRESH_MS` | 连续 30 秒没有正在运行的轮次后降频 |
| 进入空闲的判定 | **30 s** | `IDLE_AFTER_MS` | 以 `summary.running` 为准；**不看轮次/步数**——长思考期间步数不变，用步数会被误判成空闲 |
| `rollout` 文件监听 | **事件驱动** + 2 s 兜底 | `injector.js` | `fs.watch` 触发即时刷新；Windows 上偶发漏事件，用 2 s 轮询兜底（原来是 200 ms 轮询，全天不停） |
| health.json 心跳 | **60 s** | `setHealth` 写入节流 | 状态变化才写，不变时只补心跳，避免每秒写盘 |
| 面板刷新（运行中） | **4000 ms** | `src/shared/panel.html` `REFRESH_MS` | 面板可见时才轮询，切到后台自动暂停 |
| 面板刷新（静止） | **30000 ms** | `IDLE_MS` | 静止时数据本来就不变，没必要每分钟往返 15 次 |
| 底栏自检 | **1500 ms** | `src/bar/injected.js` | 页面结构变化后把底栏补回来（配合 MutationObserver） |
| 底栏跟随 | **逐帧（rAF）** | `injected.js` `followLoop` | 面板开关时输入框只移动不改宽，`ResizeObserver` 看不到；逐帧读一次 rect 约 0.0025 ms，没变化就不写样式 |

### 缓存与超时

| 项 | 值 | 位置 | 依据 |
| --- | --- | --- | --- |
| 额度缓存 TTL（有值） | **3600 s** | `src/shared/server.py` `_QUOTA_TTL_OK` | 实测服务端聚合几小时才变一次（多条会话的 `data_as_of` 是同一时间），15 分钟刷新只是重复请求 |
| 额度缓存 TTL（未归属） | **7200 s** | `_QUOTA_TTL_MISSING` | 未归属的会话不会因为等待就出现 |
| 额度缓存条目上限 | **20** | `_QUOTA_CACHE_KEEP` | 防 `quota-cache.json` 无限增长；只接受 UUID 作为 key |
| 额度接口超时 | **6 s** | `_QUOTA_TIMEOUT` | 失败就显示 `—`，不拖住面板 |
| CDP 连接超时 | **5 s** × 3 个候选 | `injector.js` | 依次尝试 `127.0.0.1` / `[::1]` / `localhost`，Chromium 有时只监听其中一个 |
| 安装器等待注入器 | **≤ 20 s**，轮询 | `tools/install.ps1` | 就绪判定看 `health.json` 且必须是本次启动后新写的；实测通常 1 秒内 |

### 长度限制

| 项 | 值 | 位置 | 用途 |
| --- | --- | --- | --- |
| 消息预览 | **200 字** | `server.py` `plain_text(item, 200)` | 统计/轨迹页认出"是哪一轮"，已去掉 markdown 标记 |
| 时间线消息文本 | **400 字** | `plain_text(item, 400)` | 每步事件里的消息摘要 |
| 工具输出详情 | **4000 字** | `plain_text(item, 4000)` | 轨迹页展开单条工具输出时 |
| 改动文件列表 | **前 5 个** | `server.py` | 更多就折叠 |

### 端口与路径

| 项 | 值 | 说明 |
| --- | --- | --- |
| CDP 调试端口 | **9223** | 固定；本机回环，但同机任意程序可连，见「安全说明」 |
| 单实例锁 | **9224** | 防止重复启动注入器 |
| 安装根 | `%USERPROFILE%\.codex-bar` | 底栏、插件、日志、缓存都在这里 |
| Codex 配置 | `%USERPROFILE%\.codex\config.toml` | 安装时写入市场源与插件注册 |
| 安装器测试入口 | `install.ps1 -TestHome <目录>` | 测试用：产物写进隔离目录，不碰进程/服务/调试端口/真实配置与快捷方式 |

> 想改这些值：改源码常量后重新 `./build.ps1` 并安装。不建议只调数字——比如把刷新压到 100 ms 会把 CPU 拉满，把预览调大只是更费内存。
