# 面板分页设计稿（v2 · 未实现）

> 状态：**P1+P2 已实现**（1.1.0）。P3（右侧轮次目录 rail）/ P4（磁盘索引缓存）未做。
> 实现时的落地取值：默认视口=最近、页大小=30、按钮=「跳到第 1 轮」；详见 `SURFACES.md` §二十七。
> 目标：让统计/轨迹像 DSH 一样能一路向上加载到第 1 轮，同时不把 payload 和 DOM 撑爆。
> 依据：DSH 的实现方式（`dsh-session-query` 的 seq 窗口、`dsh-session-turn-outline` 的全量目录投影、
> `dsh-client-ui-conversation` 的分页事件窗口）+ 本项目当前实测数据（2026-11-24）。

---

## 一、为什么不能靠"调大 MAX_TURNS"

当前 `MAX_TURNS = 60` 是**传输窗口**，不是数据缺失：服务端 `build_turns` 本来就有全部轮次，
截断只发生在 `payload_for` 返回给 MCP App 的那一刻。实测（当前会话，79 轮）：

| 返回内容 | 体积 |
| --- | ---: |
| 最近 60 轮 + 每步明细（当前默认） | ~444 KB |
| 全部 79 轮，不带明细 | ~238 KB |
| 40 轮，不带明细 | ~117 KB |
| 20 轮，不带明细 | ~68 KB |
| 全量轻量目录（79 轮，仅编号/步数/预览/耗时） | ~24 KB（约 300 B/轮） |

结论：

- 一次把全部内容（含明细）传给面板不现实；**全部"目录级"数据其实不大**（79 轮 24 KB，1000 轮约 300 KB）。
- DSH 的做法正是：**目录常驻（全量、极轻）+ 内容分页（一次一窗口）**。
- 所以我们不需要虚拟化全部内容，只需要两件事：一份轻量目录 + 一个可向前翻页的窗口。

## 二、数据分层（服务端）

保留现有"一层"接口，但把语义拆成三种视图。仍然是**同一个 `show_session_dashboard` 工具**，
新增参数沿用现有 `arguments` 通道（MCP App 已经靠它传 `items_for`，没有新机制）。

### 2.1 视图 A：`page`（分页窗口，面板主用）

```
arguments: { view: 'page', from: <1-based 起始轮次>, count: 30, include_items: false }
```

返回：

- `turns`: `[from, from+count)` 区间（自动 clamp 到 `[1, total]`）
- `meta`: `total_turns` / `window_from` / `window_to` / `has_earlier` / `has_later`
- 不返回 `outline`（省体积）

默认（不传 `view`）保持现在的"最近 60 轮"行为，兼容旧面板与旧测试。

### 2.2 视图 B：`outline`（全量目录）

```
arguments: { view: 'outline' }
```

返回 `outline: [{ turn, steps, user_preview, assistant_preview, duration_ms, running }]`，
全量、不含事件。预览长度对齐 DSH：prompt ≤ 50 字、回复 ≤ 120 字（实测 300 B/轮）。

用途：侧栏目录/跳转/后续服务端搜索。首版可以只用于"跳到第 1 轮"和"总轮次"。

### 2.3 视图 C：`items_for`（单轮明细，已有）

保持不变：`{ items_for: <轮次> }` 只回该轮 items。分页后展开旧轮次时，服务端窗口要扩到
包含该轮（现有 `focus` 逻辑已经在做，改成 page 语义后需要保留）。

### 2.4 兼容与迁移

- `turns_limit` 参数保留一个版本（内部转换成 `view: 'page'` 的尾部窗口），下一个版本移除。
- `meta.total_turns/showed_turns` 保留，新增 `window_from/window_to/has_earlier/has_later`。
- 面板旧代码（1.0.3 的"显示全部"按钮）在新服务端下仍然工作，避免"面板已开旧 tab、server 是新版"时翻车。

## 三、面板侧（统计 / 轨迹）

### 3.1 状态

```js
state.turnsByIndex = new Map();   // 已加载轮次（obj），按 1-based 轮次号为 key
state.loadedFrom = null;          // 已加载区间左端
state.loadedTo = null;            // 右端（含）
state.pageSize = 30;
state.anchor = null;              // 加载更早前记录的"首个可见轮次 + 偏移"
```

### 3.2 首屏

- 打开面板：`view:'page', from: max(1, total-29), count: 30, include_items:false` → 停在最新。
- 与 DSH 一致：打开会话先看当前，而不是先看第 1 轮。
- 顶部抬头沿用 1.0.3 文案：`共 N 轮 · 显示第 X–Y 轮`。

### 3.3 向上加载（核心）

- 统计表/轨迹列表的滚动容器：分别监听 `scroll`（节流 rAF），距顶部 < 300px 且
  `has_earlier` 且没有在加载 → 请求 `from: loadedFrom - 30, count: 30`。
- **滚动锚定**：请求前记录 `anchorTurn`（当前视口顶部第一条 `<tr data-turn>`）及其
  `getBoundingClientRect().top`；数据插入后 `window.scrollBy(0, 新内容高度)`，或
  `anchorEl.scrollIntoView()` 的等价补偿，保证用户看到的仍是同一轮。
- 插入方式：不重建整表，**每个分页一个 `<tbody class="dsh-page" data-from=...>` 片段**，
  按 `loadedFrom` 顺序拼装；删除/替换只影响尾部页（刷新时）。
- 到 `loadedFrom === 1` 时：显示"已到第 1 轮"轻提示，不再请求。

### 3.4 向下/刷新

- 4 秒（活动）/30 秒（静止）轮询：`view:'page', from: loadedTo-??` 取尾部窗口，
  按 `index` **合并**进 `turnsByIndex`，只更新已有轮次/追加新轮次；**不缩 `loadedFrom`**，
  已加载的旧页永远保留（刷新不会把用户翻出来的历史"收回去"）。
- 用户停在底部时保持贴底；停在中间/历史区时**不改 scrollTop**，只做行内容原地更新。

### 3.5 入口与可达性

- 保留一个「跳到第 1 轮」按钮（就是现在的「显示全部」，换成加载最早一页并滚过去），
  给键盘用户和不方便滚千行的场景一个直达入口。
- 搜索框（轨迹）：首版仍只搜**已加载区间**，抬头注明"在已加载的 X 轮内搜索"；
  服务端全量搜索（基于 outline）放二期。

### 3.6 不做的事（首版）

- 不做完整虚拟化（stats/trace 行高可变、展开行更高，虚拟化成本高且容易出锚定 bug）。
  先用"分页窗口 + 分块 tbody + 滚动锚定"，实测 500 行内渲染 < 16ms 再决定要不要虚拟化。
- 不做常驻磁盘索引（DSH 的 SQLite 式缓存）——那是二期，见第六节。

## 四、关键取舍

| 方案 | 效果 | 成本 | 决定 |
| --- | --- | --- | --- |
| **A. 滚动分页 + 全量轻量目录**（本稿） | 能滚到第 1 轮；单次 payload ≤ ~70 KB；任意长会话可看 | 服务端 + 面板中等改动；滚动锚定要仔细测 | **推荐** |
| B. 右侧"轮次目录" rail（更接近 DSH） | 一眼看到全部轮次，点任意轮跳转 | 多一套 UI + 预览文案 + 跳转加载态 | 二期 |
| C. 维持 1.0.3「显示全部」 | 一次点击看全部目录级数据 | 1000 轮时 ~300 KB + 千行 DOM；越大会话越慢 | 作为过渡保留按钮 |
| D. 常驻磁盘索引（DSH 式） | 重启/切换秒开，跨进程复用解析结果 | 需要索引文件格式、失效校验、并发写 | 二期（按性能实测再定） |

## 五、测试与验收（写进套件前要能失败）

**服务端单测（`test_server.py`）**

1. `page` clamp：`from=1/count=30` 在 79 轮会话上返回 1..30；`has_earlier=false`、`has_later=true`。
2. `from` 越界（0 / >total）：clamp 后不崩，`window_*` 自洽。
3. `items_for` 命中旧轮次时，返回的窗口必须包含该轮（现有 `focus` 语义保持）。
4. `outline` 行数 == `total_turns`，预览长度 ≤ 50/120。

**面板契约（`panel-contract.js`）**

5. 向上滚动触发一次 `page` 请求，`from` 为 `loadedFrom-30`，请求参数正确。
6. 连续加载到 `loadedFrom=1`：统计表行数 == `total_turns`，首行是"第 1 轮"，内容与生产 payload 对账。
7. **滚动锚定**：prepend 前后，视口顶部同一轮的 `top` 偏移变化 < 1 行高（~24px）。
8. 刷新（lite）不缩 `loadedFrom`、不改 `scrollTop`，并把新轮次追加到尾部。
9. 轨迹页同样适用（共用一个分页容器）。

**故障注入（每条都要先红后绿）**

- `page` 的 `from/count` 推导 off-by-one（`from: loadedFrom-30` 变成 `-29`）→ 断言 5/6 红；
- prepend 后不做锚定补偿 → 断言 7 红；
- 刷新用新窗口整体替换而不是合并 → 断言 8 红。

**性能门槛（`perf-check` 或契约里加软阈值）**

- 页请求（服务端到面板渲染完成）< 300 ms（本机）；
- 单次 payload ≤ 120 KB（`count=30`、无明细，实测 ~92 KB）；
- 79 轮全加载后统计表滚动掉帧 < 2 帧/秒（不阻塞主线程）。

## 六、分期

| 期 | 内容 | 产出 | 风险 |
| --- | --- | --- | --- |
| **P1** | 服务端 `view: page/outline` + meta + 单测 + 故障注入 | 面板可拿到分页数据，旧行为不变 | 低 |
| **P2** | 面板滚动分页 + 锚定 + 刷新合并 + 契约断言 | 统计/轨迹能滚到第 1 轮 | 中（锚定/滚动） |
| **P3** | 右侧轮次目录 rail + 点击跳转（可选） | 最接近 DSH 的"第 1 轮永远可见" | 中 |
| **P4** | 服务端磁盘索引缓存（可选） | 重启/换会话秒开 | 高（索引失效/并发） |

建议先做 P1+P2，一次发布（1.1.0），P3/P4 看实际使用再定。
